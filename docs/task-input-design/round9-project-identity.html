The project is the personality

Re-cut for a personal list: scheduling leads, the project gives the task its identity, notes and subtasks fold away until asked for. Every accent in the modal — the selected day, the completion ring, the chips, the cover artwork — is derived from the project instead of a fixed indigo.

Switch projects below and watch the whole editor re-skin. That's the point: you should know you're in Health and not Home before you've read a word.

What it does

  • Calendar is the first real content — two weeks visible without expanding, ~200 px from the top.
  • The cover gives the task an identity you read before any text. Project, emoji, colour and texture all come from data you already store.
  • Notes and subtasks fold to one line each, with a preview so folding never hides that something's there.

What it costs

What it does

  • The calendar gets the widest cells of any option — ~86 px squares, so busyness dots and day labels have real room.
  • Cover flair plus a rail: identity at the top, properties down the side, scheduling in the middle where the eye lands.
  • Scales best as the list grows — the rail can take location reminders, repeat rules, or whatever comes next without re-cutting the layout.

What it costs

  • 900 px for a personal task list is a lot of modal. Editing "buy milk" shouldn't feel like opening a Jira ticket.
  • Needs a sub-1000 px story — most likely collapsing to option A.
  • The rail is mostly empty for a typical personal task with no deadline and no estimate.

Notes or description?

Keep "Notes". The two words set different expectations, and the difference matters more now that this is a personal list.

"Description" implies the field defines the task — that a task without one is under-specified. That's true on a work tracker where a ticket is a contract between people. Linear, Asana and Todoist all say Description for exactly that reason.

"Notes" implies a scratch space you add to when you have something to add. An empty Notes field is normal; an empty Description field feels like a gap. For a list where most tasks will never have one, the word that makes emptiness normal is the right word. Things 3 and Apple Reminders both land here.

It also matches what the app already says on mobile — the placeholder is "Tap to add notes…" — and it survives the fold: a folded row reading Notes · Blocked on the signing key… is honest, where Description on one line reads like a truncated spec.

The column stays description. That's an internal identifier, same class as the repo being do-done while the product is DoDone — no migration needed, and nothing user-facing says the word.

Where I'd land

  • A. It's the one that answers all three asks at once — calendar leads, project carries the flair, notes and subtasks fold — and it does it at 660 px without a two-column layout to maintain.
  • C is A with the volume up. Worth building if the cover reads well in A and you want more of it; the full-bleed calendar panel is a one-class change from A.
  • B is the fallback if the cover ever feels like decoration. Everything else in A survives without it.
  • D is the one to skip for now. It's a work-tracker layout, and the brief just moved away from work.

What this needs from the data

  • Projects already carry color and icon — that's the colour, the emoji and the whole cover, with no new columns.
  • The texture is derived: hash the project id to one of ~5 patterns, so two same-hue projects still read apart. Deterministic, nothing stored.
  • The no-project case needs a real answer, not a grey box. Options: use the workspace accent, use a subtle neutral texture, or hide the cover and fall back to B's layout.
  • Contrast is the open risk — a light project colour (amber, lime) against white cover text needs a luminance check, not a fixed white.
