Task input · Round 7 — Done button as exit + saved indicator

A bottom-right Done button on desktop (and full-width Done at the bottom on mobile) gives users the conventional "exit" affordance they expect, while doubling as the saved confirmation. The green-check-in-a-circle inside the indigo button signals "all good, saved" at a glance.

The Done button's anatomy:
  • Green checkmark in a circle — communicates "everything's saved". Briefly pulses on each autosave
  • "Done" primary label — the action verb users expect
  • "all saved" sub-label — explicit reassurance that nothing's lost on exit
  • Esc kbd hint on desktop only — same as clicking
The top-bar autosave indicator got simpler: just the small green pulse + "auto-save" tooltip. The bottom button carries the saved messaging now, so the top bar is just a quiet heartbeat that tells you "yes, this is autosaving" if you ever look at it.

The cancel path is unchanged: "↶ Undo all changes" (desktop top-right) and "↶ Cancel" (mobile top-left) revert everything since opening. Clicking Done or the X commits the autosaved state.
